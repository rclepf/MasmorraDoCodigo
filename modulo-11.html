Segurança e integridade em jogos

Ligação com a UC anterior

Na UC anterior você cuidou dos direitos sobre o material: de onde vêm as imagens, os sons e as fontes, e o que você pode ou não usar. A segurança de dados é o mesmo cuidado, só que voltado ao jogador: o que o jogo guarda, quem pode mexer e o que pode dar errado.

Dica de produção. Antes de pensar em proteger alguma coisa, pergunte quanto custa se ela for violada. Em um jogo offline para um jogador, um save editado só afeta quem trapaceou. Em um jogo com ranking ou compras, o custo é bem maior.

A regra de ouro: o cliente é do jogador

Tudo o que roda no computador do jogador pode ser lido, copiado e modificado por ele: o save, a memória, o próprio código. Por isso:

  • não existe proteção perfeita do lado do cliente; existe aumentar o esforço para trapacear;
  • nunca embuta no jogo uma chave de serviço, senha ou token que, se descoberto, dê acesso a algo valioso;
  • qualquer regra importante (ranking, compra, moeda paga) precisa ser conferida em um servidor, que o jogador não controla.

Primeira defesa: nunca confiar no que foi lido

Mesmo sem assinatura, todo dado que entra no jogo, vindo de arquivo, rede ou digitação, passa por uma validação. Ela é barata e já barra a maioria dos erros e dos truques:

ValidadorDeSave.cs 
using UnityEngine;

public static class ValidadorDeSave
{
    private const int PontosMaximos = 1_000_000;
    private const int VidaMaxima = 10;
    private const float LimiteDoMapa = 500f;

    public static DadosSave Sanear(DadosSave d)
    {
        d.pontos = Mathf.Clamp(d.pontos, 0, PontosMaximos);
        d.vida = Mathf.Clamp(d.vida, 1, VidaMaxima);

        Vector3 p = d.posicao;
        bool valida = !float.IsNaN(p.x) && !float.IsNaN(p.y) && !float.IsNaN(p.z)
                      && Mathf.Abs(p.x) <= LimiteDoMapa && Mathf.Abs(p.y) <= LimiteDoMapa && Mathf.Abs(p.z) <= LimiteDoMapa;
        if (!valida) d.posicao = Vector3.zero;

        d.itens.RemoveAll(i => i == null || string.IsNullOrEmpty(i.nome) || i.quantidade < 0 || i.quantidade > 999);
        if (d.fase == null || d.fase.Length > 40) d.fase = "Masmorra01";
        return d;
    }
}

Repare que não perguntamos "quem editou?", só "esse valor é possível no jogo?". Um valor impossível é corrigido para um valor válido. Essa técnica também protege contra erros honestos, como um arquivo cortado pela metade.

Segunda defesa: detectar edição com assinatura

Uma assinatura (HMAC, ou código de autenticação de mensagem) é um resumo do conteúdo, calculado com uma chave. Se o arquivo mudar um caractere, o resumo deixa de bater. Guardamos o resumo junto do save e conferimos ao carregar:

SaveAssinado.cs 
using System;
using System.IO;
using System.Security.Cryptography;
using System.Text;
using UnityEngine;

public static class SaveAssinado
{
    // Chave de exemplo. Ela existe no jogo, então um jogador determinado pode encontrá-la.
    private static readonly byte[] chave = Encoding.UTF8.GetBytes("troque-esta-chave-no-seu-projeto");

    private static string Caminho => Path.Combine(Application.persistentDataPath, "seguro.json");

    public static string Assinar(string json)
    {
        using var hmac = new HMACSHA256(chave);
        return Convert.ToBase64String(hmac.ComputeHash(Encoding.UTF8.GetBytes(json)));
    }

    public static void Salvar(DadosSave dados)
    {
        string json = JsonUtility.ToJson(dados);
        // Primeira linha: assinatura. Restante: conteúdo
        File.WriteAllText(Caminho, Assinar(json) + "\n" + json);
    }

    public static bool TentarCarregar(out DadosSave dados)
    {
        dados = new DadosSave();
        if (!File.Exists(Caminho)) return false;

        string[] partes = File.ReadAllText(Caminho).Split(new[] { '\n' }, 2);
        if (partes.Length != 2) return false;

        bool integro = CryptographicOperations.FixedTimeEquals(
            Encoding.UTF8.GetBytes(partes[0]), Encoding.UTF8.GetBytes(Assinar(partes[1])));
        if (!integro) return false;

        dados = ValidadorDeSave.Sanear(JsonUtility.FromJson<DadosSave>(partes[1]));
        return true;
    }
}

Quando TentarCarregar devolve falso, o jogo decide: recomeçar, avisar o jogador, ou aceitar o save mas marcá-lo como "modificado" e excluí-lo de rankings. Essa é uma decisão de design, não de código.

O que isso protege e o que não protege. Protege contra quem abre o JSON no bloco de notas e muda um número. Não protege contra quem decompila o jogo, acha a chave e assina um save falso, e a chave não pode ser escondida de verdade no cliente. Por isso dizemos que a assinatura dificulta, não que ela impede. Para o que realmente importa, é preciso um servidor.

Salve e confira o arquivo

Chame SaveAssinado.Salvar e abra o arquivo: a primeira linha é a assinatura e as demais são o save.

Adultere

Mude pontos no arquivo e carregue. O resultado precisa ser falso, e o jogo precisa reagir sem travar.

Teste o saneamento

Escreva um save sem assinatura com pontos de 9 bilhões e chame Sanear: o valor deve voltar ao limite.

Checkpoint: um save editado à mão é recusado, um save válido carrega, e valores impossíveis são corrigidos para valores possíveis.

Dados pessoais e privacidade

Se o jogo coleta qualquer informação que identifique uma pessoa (nome, e-mail, idade, localização, identificadores de aparelho), a Lei Geral de Proteção de Dados (LGPD, Lei 13.709/2018) se aplica. Para um projeto de curso, os princípios práticos são:

  • coletar o mínimo: se o jogo funciona sem o e-mail, não peça o e-mail;
  • informar o que é coletado e para quê, em linguagem simples, antes da coleta;
  • guardar com cuidado: nunca em texto puro quando for sensível, e nunca no repositório público;
  • permitir apagar: um botão que remove o save e os dados do jogador;
  • cuidado extra com crianças e adolescentes: a lei exige consentimento de um responsável para menores de 12 anos e atenção redobrada até os 18.
Regra do repositório. Senhas, chaves e tokens nunca vão para o Git. Use um arquivo local ignorado pelo .gitignore e, se um segredo já foi enviado por engano, considere-o vazado e troque-o.

Checkpoint do módulo

  • um validador que corrige ou rejeita dados impossíveis;
  • um save assinado que detecta edição simples;
  • um teste documentado de adulteração e a reação escolhida do jogo;
  • um texto curto com o que é coletado de dados pessoais (ou a afirmação de que nada é coletado);
  • uma lista com três limites da proteção feita e o que seria necessário para ir além.

Problemas comuns

Meu próprio save válido é recusado

Qualquer mudança no JSON depois de assinar, até uma quebra de linha, invalida a assinatura. Assine exatamente o texto que será gravado e leia exatamente o que foi gravado.

A assinatura quebra quando acrescento um campo

Saves antigos foram assinados com a estrutura antiga, mas o texto lido ainda é o mesmo, então a assinatura segue válida. O problema aparece se você reserializa antes de conferir: confira sempre o texto original.

Achei que a chave estava escondida

Em um jogo que roda no computador do jogador, qualquer chave pode ser encontrada. Trate a assinatura como obstáculo, não como cofre.

Salvei uma senha no Git sem querer

Remover o arquivo no commit seguinte não apaga o histórico. Troque a senha imediatamente e trate-a como comprometida.
