Ligação com a UC anterior

Na UC anterior você organizou pastas, nomes e versões dos seus arquivos para que a equipe encontrasse tudo sem perguntar. Padrões de projeto fazem o mesmo com o código: são receitas de organização conhecidas por todos, de modo que, ao ler GerenteDeJogo.Instancia, qualquer colega entende a intenção.

Dica de produção. Use padrões para resolver um problema que você já está sentindo, não para enfeitar o projeto. Se o código está simples e funciona, ele está bom.

Singleton: uma instância, acesso global

O Singleton garante que exista só uma cópia de uma classe e oferece um ponto de acesso fácil. É ideal para o que é, por natureza, único no jogo: pontuação, fase atual, estado de pausa.

GerenteDeJogo.cs 
using System;
using UnityEngine;

public class GerenteDeJogo : MonoBehaviour
{
    public static GerenteDeJogo Instancia { get; private set; }

    public int Pontos { get; private set; }
    public event Action<int> AoMudarPontos;

    void Awake()
    {
        // Se já existe outro gerente, este é descartado
        if (Instancia != null && Instancia != this)
        {
            Destroy(gameObject);
            return;
        }
        Instancia = this;
    }

    void OnDestroy()
    {
        if (Instancia == this) Instancia = null;
    }

    public void AdicionarPontos(int valor)
    {
        Pontos += valor;
        AoMudarPontos?.Invoke(Pontos);
    }
}

Qualquer script agora pode escrever GerenteDeJogo.Instancia.AdicionarPontos(10), sem arrastar referência no Inspector.

Cuidado com o abuso. O Singleton é conveniente demais: se tudo vira Singleton, o código fica emaranhado e difícil de testar. Reserve-o para poucos gerentes realmente únicos e prefira passar referências nos demais casos.

Observer: avisar sem acoplar

Repare no event Action<int> AoMudarPontos do gerente. Ele é o Observer: quem tem interesse se inscreve, e o gerente avisa todos sem saber quem são. O placar, o som e as conquistas podem ser adicionados ou removidos sem alterar o gerente.

Placar.cs 
using UnityEngine;

public class Placar : MonoBehaviour
{
    private int exibido;

    void OnEnable()
    {
        GerenteDeJogo.Instancia.AoMudarPontos += Atualizar;
        Atualizar(GerenteDeJogo.Instancia.Pontos);
    }

    void OnDisable()
    {
        if (GerenteDeJogo.Instancia != null)
            GerenteDeJogo.Instancia.AoMudarPontos -= Atualizar;
    }

    private void Atualizar(int pontos)
    {
        exibido = pontos;
        Debug.Log($"Pontos: {exibido}");
    }

    void OnGUI()
    {
        GUI.Label(new Rect(16, 16, 200, 30), $"Pontos: {exibido}");
    }
}

A regra de ouro: todo += precisa de um -= no OnDisable. Sem isso, um objeto destruído continua na lista de avisos e o jogo dá erros estranhos.

Compare com o UnityEvent do módulo 6: o UnityEvent é um Observer configurado pelo Inspector (bom para designers); o event do C# é um Observer configurado pelo código (mais rápido e seguro para sistemas internos).

Conecte o coletável

No Coletavel do módulo 6, depois de adicionar o item ao inventário, chame GerenteDeJogo.Instancia.AdicionarPontos(dados.valor).

Crie o gerente na cena

Crie um objeto vazio Gerente com o componente GerenteDeJogo e outro Interface com o Placar. O gerente precisa existir antes do placar: ajuste a ordem em Edit > Project Settings > Script Execution Order se aparecer erro de referência nula.

Adicione um segundo ouvinte

Crie um script que toca um som a cada 100 pontos, inscrito no mesmo evento. O gerente não muda uma linha: é isso que desacoplado significa.

Checkpoint: coletar itens atualiza o placar e o segundo ouvinte, e o gerente não conhece nenhum dos dois.

Object Pool: reaproveitar em vez de criar

Criar (Instantiate) e destruir (Destroy) objetos o tempo todo gera lixo de memória e pequenos travamentos. O Object Pool mantém uma reserva: pede-se um objeto, usa-se, devolve-se à reserva em vez de destruir. A Unity já traz o ObjectPool<T> pronto.

Projetil.cs 
using UnityEngine;
using UnityEngine.Pool;

public class Projetil : MonoBehaviour
{
    [SerializeField] private float velocidade = 12f;
    [SerializeField] private float tempoDeVida = 2f;

    private IObjectPool<Projetil> pool;
    private float nascimento;

    public void Configurar(IObjectPool<Projetil> origem) => pool = origem;

    void OnEnable() => nascimento = Time.time;

    void Update()
    {
        transform.position += transform.forward * velocidade * Time.deltaTime;
        if (Time.time - nascimento > tempoDeVida) pool.Release(this);
    }
}
Lancador.cs 
using UnityEngine;
using UnityEngine.Pool;

public class Lancador : MonoBehaviour
{
    [SerializeField] private Projetil prefab;
    [SerializeField] private Transform bocal;

    private ObjectPool<Projetil> pool;

    void Awake()
    {
        pool = new ObjectPool<Projetil>(
            createFunc: () => { var p = Instantiate(prefab); p.Configurar(pool); return p; },
            actionOnGet: p => p.gameObject.SetActive(true),
            actionOnRelease: p => p.gameObject.SetActive(false),
            actionOnDestroy: p => { if (p != null) Destroy(p.gameObject); },
            defaultCapacity: 10, maxSize: 50);
    }

    public void Disparar()
    {
        Projetil p = pool.Get();
        p.transform.SetPositionAndRotation(bocal.position, bocal.rotation);
    }
}

Repare no if (p != null) ao destruir: ao sair do Play Mode a Unity esvazia o pool e os objetos já podem ter sido destruídos; sem essa guarda, o Console mostra um erro de referência perdida.

Os quatro parâmetros contam a vida do objeto: criar quando a reserva está vazia, ativar ao pedir, desativar ao devolver e destruir se a reserva estourar o limite. Use o Profiler (Window > Analysis > Profiler) para comparar: com o pool, a coluna GC Alloc fica próxima de zero.

Checkpoint: disparar 200 projéteis em sequência não cria mais de 50 objetos na Hierarchy, e o Profiler mostra pouca alocação de memória.

Checkpoint do módulo

  • um gerente único (Singleton) com pontuação ou estado da fase;
  • pelo menos dois sistemas diferentes inscritos em um evento, sem o gerente conhecê-los;
  • um Object Pool aplicado a um objeto que se repete no jogo;
  • um print do Profiler comparando o jogo com e sem o pool;
  • um parágrafo explicando por que cada padrão foi (ou não foi) usado.

Problemas comuns

NullReferenceException em GerenteDeJogo.Instancia

O placar acordou antes do gerente. Garanta que o gerente exista na cena e ajuste a ordem de execução, ou inscreva-se no Start em vez de OnEnable.

Aparecem dois gerentes na cena

O Destroy do segundo só ocorre no Awake. Se ele estiver em cenas diferentes, mantenha um só na cena inicial.

Erros depois de destruir um objeto inscrito no evento

Faltou o -= no OnDisable. Todo += precisa ter o seu par.

O projétil reaparece no lugar antigo

No OnEnable, reinicie o estado (tempo de nascimento, velocidade). Objetos reaproveitados guardam o que tinham ao ser devolvidos.
