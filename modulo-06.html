Ligação com a UC anterior

Quando você montou o baú no Blender, ele era feito de partes: corpo, tampa, ferragens, cada uma com seu material. Componentes seguem a mesma lógica: em vez de um objeto gigante, um objeto leve com peças encaixáveis.

Seus itens viram dados. As poções, moedas, chaves e armas que você modelou ou desenhou ganham um arquivo de dados (nome, ícone, valor) que o jogo lê. Para criar um item novo, basta criar um arquivo, sem programar.

Composição no lugar de herança

No módulo 5, vimos que herdar cria hierarquias rígidas. Na programação orientada a componentes, cada característica vira um componente independente:

ComponenteResponsabilidadeUsado por
VidaGuarda pontos de vida, recebe dano, avisa quando chega a zeroJogador, inimigos, caixas quebráveis, portas
AtaqueCausa dano em quem entra no alcanceInimigos, armadilhas, o herói
ColetavelDá um item ao herói ao toqueMoedas, chaves, poções
InventarioGuarda o que o herói carregouJogador

Uma armadilha de espinhos tem Ataque mas não precisa de Vida. Uma caixa quebrável tem Vida mas não ataca. O herói tem os dois. Nenhuma herança foi necessária.

O componente Vida

Para que qualquer coisa possa levar dano sem saber quem a atingiu, defina um contrato com uma interface:

IDanificavel.cs 
public interface IDanificavel
{
    void ReceberDano(int dano);
}
Vida.cs 
using UnityEngine;
using UnityEngine.Events;

public class Vida : MonoBehaviour, IDanificavel
{
    [SerializeField] private int vidaMaxima = 3;

    public int Atual { get; private set; }
    public int Maxima => vidaMaxima;

    public UnityEvent aoMudar;
    public UnityEvent aoMorrer;

    void Awake() => Atual = vidaMaxima;

    public void ReceberDano(int dano)
    {
        if (Atual <= 0) return;

        Atual = Mathf.Max(0, Atual - dano);
        aoMudar?.Invoke();
        if (Atual == 0) aoMorrer?.Invoke();
    }

    public void Curar(int quantidade)
    {
        Atual = Mathf.Min(vidaMaxima, Atual + quantidade);
        aoMudar?.Invoke();
    }
}

Os UnityEvents aparecem no Inspector. Em aoMorrer, arraste o objeto e escolha o que acontece: destruir, tocar um som, abrir uma porta. O designer da equipe configura sem tocar no código. No módulo 9, você verá como fazer isso com o padrão Observer, por código.

Refatore o Inimigo

Na classe Inimigo do módulo 5, remova vidaMaxima, vidaAtual e o método ReceberDano. Adicione [RequireComponent(typeof(Vida))] sobre a classe. No inspector, configure aoMorrer do componente Vida para chamar a destruição do objeto. A vida passou a ser peça reutilizável.

Dê vida ao herói

Adicione o componente Vida ao Jogador com 5 de vida máxima. O contador de vida da interface pode ser atualizado ligando o evento aoMudar.

Ataque por componente

Ataque.cs 
using UnityEngine;

public class Ataque : MonoBehaviour
{
    [SerializeField] private int dano = 1;
    [SerializeField] private float intervalo = 1f;
    [SerializeField] private LayerMask alvos;

    private float proximoAtaque;

    void OnTriggerStay(Collider outro)
    {
        if (Time.time < proximoAtaque) return;
        if ((alvos.value & (1 << outro.gameObject.layer)) == 0) return;

        if (outro.TryGetComponent(out IDanificavel alvo))
        {
            alvo.ReceberDano(dano);
            proximoAtaque = Time.time + intervalo;
        }
    }
}

Coloque o Ataque em um objeto com collider Is Trigger em volta do inimigo, de uma armadilha ou da espada do herói. O código não pergunta "é jogador? é inimigo?": pergunta apenas "isso pode ser danificado?". TryGetComponent procura o componente sem gerar erro quando ele não existe.

Checkpoint: o slime perto do herói reduz a vida dele a cada segundo, uma armadilha com o mesmo componente faz o mesmo e a vida do herói zera uma única vez.

Itens descritos por dados: ScriptableObject

O som de coleta também passa a vir do item: o SomColeta do módulo 4 pode ser removido, e cada ItemDados aponta para o próprio clipe. Hoje o Coletavel usa um enum com dois tipos. Para adicionar uma poção de cura, você teria que editar o código. Um ScriptableObject guarda dados em arquivo, e cada item novo é um arquivo novo.

ItemDados.cs 
using UnityEngine;

[CreateAssetMenu(fileName = "NovoItem", menuName = "Masmorra/Item")]
public class ItemDados : ScriptableObject
{
    public string nome = "Moeda";
    public Sprite icone;
    public int valor = 1;
    public bool curaVida;
    public bool abrePorta;
    public AudioClip som;
}
Coletavel.cs (nova versão) 
using UnityEngine;

public class Coletavel : MonoBehaviour
{
    [SerializeField] private ItemDados dados;
    [SerializeField] private float velocidadeGiro = 90f;

    void Update()
    {
        transform.Rotate(Vector3.up, velocidadeGiro * Time.deltaTime, Space.World);
    }

    void OnTriggerEnter(Collider outro)
    {
        if (!outro.CompareTag("Player")) return;

        if (dados.curaVida && outro.TryGetComponent(out Vida vida))
            vida.Curar(dados.valor);

        if (outro.TryGetComponent(out Inventario inventario))
            inventario.Adicionar(dados);

        if (dados.som != null)
            AudioSource.PlayClipAtPoint(dados.som, transform.position);

        Destroy(gameObject);
    }
}
Inventario.cs (nova versão) 
using System.Collections.Generic;
using UnityEngine;

public class Inventario : MonoBehaviour
{
    private readonly Dictionary<ItemDados, int> itens = new Dictionary<ItemDados, int>();

    public int Quantidade(ItemDados item) => itens.TryGetValue(item, out int n) ? n : 0;

    public void Adicionar(ItemDados item)
    {
        itens[item] = Quantidade(item) + 1;
        Debug.Log($"{item.nome}: {itens[item]}");
    }

    public bool UsarItemQueAbrePorta()
    {
        foreach (var par in itens)
        {
            if (par.Key.abrePorta && par.Value > 0)
            {
                itens[par.Key] = par.Value - 1;
                return true;
            }
        }
        return false;
    }
}

Crie os itens

Clique com o botão direito em Assets/Dados e escolha Create > Masmorra > Item. Crie Moeda, Chave e PocaoDeCura, cada uma com nome, ícone (sua pixel art da Atividade 06) e valor.

Atualize os prefabs

Em cada prefab coletável, arraste o arquivo de dados correspondente. A Porta do módulo 3 passa a chamar UsarItemQueAbrePorta() no lugar de UsarChave().

Crie um item sem programar

Crie uma Poção Grande com valor 3, duplique o prefab da poção, troque o dado e coloque na cena. Nenhuma linha de código foi alterada.

Checkpoint do módulo

  • pelo menos 3 componentes reutilizáveis independentes no jogo da equipe (por exemplo, Vida, Ataque e um de mecânica própria);
  • uma interface que permita tratar objetos diferentes do mesmo modo;
  • pelo menos 4 itens definidos como ScriptableObject, um deles com efeito diferente dos demais;
  • um evento configurado pelo Inspector ligando dois componentes.

As instruções completas estão na Atividade Prática C06.

Problemas comuns

A vida do inimigo não diminui ao ser atacado

O Ataque só funciona se o alvo tem collider, a camada está em alvos e o objeto tem um componente que implementa IDanificavel. Veja também se o collider do Ataque está como Is Trigger.

O ScriptableObject não aparece no menu Create

O arquivo precisa ter o mesmo nome da classe e a linha [CreateAssetMenu] logo acima dela. Verifique se não há erros no Console.

Os dados do item voltam ao normal ao parar o jogo

Alterações em objetos da cena durante o Play são perdidas, mas alterações em arquivos ScriptableObject são mantidas. Se o item perdeu o valor, você alterou o objeto da cena e não o arquivo.

Mensagem de erro de referência nula no Coletavel

O campo dados está vazio no prefab. Arraste o arquivo de dados para o Inspector.
