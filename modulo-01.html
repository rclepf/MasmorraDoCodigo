A ponte entre as duas UCs

Na UC Planejamento e Produção de Elementos Multimídia de Jogos Digitais você produziu os elementos de um jogo: logotipo, arte, pixel art, modelos 3D, texturas, vídeo e som. Nesta UC você faz esses elementos funcionarem: o código dá movimento, regras e resposta ao jogador.

Um jogo digital só existe quando as duas partes se encontram. Sem assets, o código controla cubos cinzas. Sem código, os assets ficam em uma pasta. Por isso, nada do que você fez antes será descartado.

Pense como estúdio. Em empresas, artistas e programadores trabalham em paralelo e se encontram na engine. A qualidade do que você entrega na primeira UC define a facilidade de trabalho nesta. Modelos sem Apply Scale, UV bagunçada ou texturas enormes aparecem aqui como bugs.

O jogo-guia

Durante a UC você constrói Masmorra do Código: um dungeon crawler 3D em terceira pessoa. O herói explora salas, abre portas com chaves, coleta moedas e poções, enfrenta slimes e esqueletos e salva o progresso.

Cada módulo acrescenta uma peça a esse jogo. A equipe faz o mesmo percurso em outro jogo 3D, com a mecânica que escolher (plataforma, stealth, survival, corrida, puzzle).

GDD enxuto

O Game Design Document (GDD) registra o que o jogo é antes de existir código. Um GDD de duas páginas basta nesta fase, desde que responda estas perguntas:

SeçãoPerguntaNo jogo-guia
ConceitoO que o jogador faz em uma frase?Explora masmorras 3D, derrota inimigos e escapa com o tesouro.
PúblicoPara quem e em que plataforma?Jogadores casuais, PC, partidas de 10 a 15 minutos.
MecânicasQuais verbos o jogador usa?Andar, atacar, abrir porta, coletar, usar poção.
Câmera e controlesComo se vê e se controla?Terceira pessoa; WASD e mouse; espaço ataca.
ProgressãoComo se ganha ou perde?Vence ao chegar à sala final; perde com vida zerada.
EscopoO que fica de fora?Sem multiplayer, sem geração de som própria.
Escopo é decisão de projeto. Uma lista do que o jogo não terá evita que o semestre acabe com metade das mecânicas inacabadas.

Preparando o ambiente

Instale a Unity

Instale o Unity Hub e, por ele, o Editor na versão LTS indicada pelo professor, com o módulo de build para Windows. Todos da turma usam a mesma versão, para os projetos abrirem em qualquer máquina.

Escolha a IDE

Use Visual Studio Community com a carga de trabalho "Desenvolvimento de jogos com Unity", ou outra IDE aprovada pelo professor. Em Unity, abra Edit > Preferences > External Tools e selecione a IDE em External Script Editor.

Crie o projeto

No Hub, escolha New project e um template 3D. Nomeie como MasmorraDoCodigo (jogo-guia) ou com o nome do jogo da equipe. Evite acentos e espaços no nome da pasta.

Ajuste o projeto para versionamento

Em Edit > Project Settings > Editor, confira Version Control Mode: Visible Meta Files e Asset Serialization Mode: Force Text. Com isso, o Git consegue comparar cenas e prefabs.

Copie as pastas

Descompacte o zip e arraste Models e Textures para a pasta Assets. A Unity importa cada OBJ e cria um material por cor.

Monte uma sala de 3 por 3 tiles

Se você tem o galpão da Atividade 10.8, use-o como primeira sala. Caso contrário, use o kit. Cada tile do kit mede 4 por 4 metros. Posicione nove Floor_Tile em múltiplos de 4 no eixo X e Z, e cerque a sala com Wall. Deixe uma abertura com Wall_Door.

Teste a escala

Crie um Capsule de altura 2 como jogador provisório e confira se cabe na porta. Se algo estiver gigante ou minúsculo, o problema é de escala de importação: confira Scale Factor no modelo.

Importe um modelo seu do Blender

Pegue o baú (ou outro objeto) que você exportou na Atividade 12 e arraste o .fbx para Assets/Models. Selecione o arquivo e confira no Inspector, na aba Model, o Scale Factor e, na aba Materials, se as texturas foram reconhecidas. Coloque o baú ao lado do Chest do kit: se os tamanhos diferirem muito, falta Apply Scale ou conferir a unidade no Blender.

Salve como Prefab

Arraste a sala da hierarquia para Assets/Prefabs. Prefabs permitem reutilizar a sala sem copiar objeto por objeto.

Checkpoint: a sala aparece completa na aba Game, sem materiais rosa e com a capsule passando pela porta.

Primeiro script e depuração

Scripts em Unity são classes que herdam de MonoBehaviour. A engine chama Start uma vez, quando o objeto aparece, e Update a cada quadro.

Crie o script

Em Assets/Scripts, crie um C# Script chamado HelloDungeon (o nome do arquivo precisa ser igual ao nome da classe) e cole o código.

HelloDungeon.cs 
using UnityEngine;

/// <summary>Primeiro script: confirma que o ciclo de vida da Unity funciona.</summary>
public class HelloDungeon : MonoBehaviour
{
    [SerializeField] private string nomeDoJogo = "Masmorra do Código";
    private int quadros;

    void Start()
    {
        Debug.Log($"Bem-vindo a {nomeDoJogo}!");
    }

    void Update()
    {
        quadros++;
        if (quadros % 300 == 0)
            Debug.Log($"Passaram {quadros} quadros");
    }
}

Anexe e rode

Arraste o script para a capsule na hierarquia e aperte Play. Abra a aba Console: a mensagem de boas-vindas aparece uma vez, e a de quadros a cada 300 quadros. Edite nomeDoJogo no Inspector sem mexer no código.

Depure com breakpoint

Na IDE, clique na margem da linha quadros++; para criar um breakpoint e use Attach to Unity. Ao apertar Play, a execução pausa na linha. Passe o mouse sobre quadros para ver o valor e use Step Over para avançar linha a linha.

Debug.Log serve para observar o que acontece sem parar o jogo. O breakpoint serve para parar e inspecionar. Use cada um quando fizer sentido.

O repositório é o histórico do projeto e a base do trabalho em equipe. Crie .gitignore na raiz do projeto antes do primeiro commit, para não versionar pastas geradas pela Unity.

Inicialize e faça o primeiro commit

git init
git add .
git commit -m "feat: projeto Unity inicial com sala greybox"

Trabalhe em ramos

Cada mecânica nova nasce em um ramo e volta para o principal quando funciona.

git switch -c feat/hello-dungeon
git add Assets/Scripts
git commit -m "feat: HelloDungeon com Debug.Log"
git switch main
git merge feat/hello-dungeon

Publique no repositório remoto

Crie um repositório vazio no GitHub e conecte-o.

git remote add origin <URL-do-repositorio>
git push -u origin main
Boas mensagens de commit dizem o que mudou e por quê, em uma linha. "arrumei" não ajuda ninguém, nem você daqui a um mês.

Checkpoint do módulo

Ao final do módulo, o projeto da equipe deve ter:

  • inventário de assets da equipe, com a origem de cada um na UC anterior;
  • GDD de duas páginas e tabela de requisitos (mínimo 6 RF e 3 RNF);
  • diagrama de classes com pelo menos 5 classes;
  • projeto Unity com sala greybox, pelo menos 2 assets produzidos pela equipe na UC anterior e o HelloDungeon funcionando;
  • repositório Git com no mínimo 3 commits e um ramo mesclado.

As instruções completas estão na Atividade Prática do módulo.

Problemas comuns

Os modelos aparecem rosa

O pipeline de render do projeto não reconheceu os materiais importados. Em projetos com template URP, use Edit > Rendering > Materials > Convert Built-in Materials to URP ou crie materiais URP/Lit e reatribua as cores.

Meu modelo do Blender aparece gigante, minúsculo ou deitado

Confira no Blender se a escala foi aplicada (Ctrl+A > Scale) e se o eixo da exportação FBX está correto. Na Unity, ajuste Scale Factor no Inspector do modelo. Este é o motivo de as Atividades 11 e 12 insistirem em organização e exportação.

O script não aparece ao arrastar para o objeto

Geralmente há erro de compilação em outro script ou o nome do arquivo difere do nome da classe. Corrija o erro vermelho no Console e confira os nomes.

A IDE não mostra sugestões de código da Unity

Confira se a IDE correta está em External Script Editor e use Assets > Open C# Project para regenerar os arquivos de projeto.

O Git mostra milhares de arquivos para commitar

O .gitignore foi criado depois do primeiro git add. Rode git rm -r --cached ., depois git add . e commite de novo.
