Ligação com a UC anterior

Na UC anterior você organizou seus arquivos de produção em pastas com nomes padronizados e planilhas de controle, para que qualquer pessoa da equipe encontrasse o que precisava. Um sistema de save faz o mesmo para o jogo: transforma o estado da partida em um arquivo organizado que pode ser guardado, lido e conferido.

Dica de produção. Liste, em papel, tudo o que o jogador espera encontrar ao voltar: fase, vida, itens, configurações. O que não está na lista não precisa ser salvo. Salvar menos é mais simples e mais seguro.

O que salvar e onde

Tipo de dadoExemploOnde guardar
Configurações levesVolume, idioma, sensibilidadePlayerPrefs
Progresso da partidaFase, vida, inventário, posiçãoArquivo JSON em persistentDataPath
Conteúdo do jogo (não muda)Itens, inimigos, falasScriptableObject (módulo 6)

Application.persistentDataPath é uma pasta que a Unity escolhe para cada sistema (no Windows, dentro de AppData) e que sobrevive a atualizações do jogo. Gravar dentro da pasta Assets só funciona no Editor e some no jogo final.

Um modelo de dados serializável

Comece separando o que é estado salvo do que são objetos da cena. Uma classe simples, marcada [Serializable], guarda só números e textos:

DadosSave.cs 
using System;
using System.Collections.Generic;
using UnityEngine;

[Serializable]
public class ItemSalvo
{
    public string nome;
    public int quantidade;
}

[Serializable]
public class DadosSave
{
    public const int VersaoAtual = 2;

    public int versao = VersaoAtual;
    public string fase = "Masmorra01";
    public int pontos;
    public int vida = 3;
    public Vector3 posicao;
    public List<ItemSalvo> itens = new List<ItemSalvo>();
}

A JsonUtility da Unity converte essa classe em texto e de volta. Ela entende campos públicos, listas e tipos como Vector3, mas não entende dicionários: por isso o inventário vira uma lista de ItemSalvo no arquivo, mesmo sendo um Dictionary no jogo.

Gravar e ler com segurança

SistemaSave.cs 
using System;
using System.IO;
using UnityEngine;

public static class SistemaSave
{
    private static string Caminho(int slot) =>
        Path.Combine(Application.persistentDataPath, $"save{slot}.json");

    public static void Salvar(DadosSave dados, int slot = 0)
    {
        string destino = Caminho(slot);
        string temporario = destino + ".tmp";

        // Grava em arquivo temporário e só então troca: queda de energia no meio não destrói o save antigo
        File.WriteAllText(temporario, JsonUtility.ToJson(dados, true));
        if (File.Exists(destino)) File.Delete(destino);
        File.Move(temporario, destino);
    }

    public static bool Existe(int slot = 0) => File.Exists(Caminho(slot));

    public static DadosSave Carregar(int slot = 0)
    {
        if (!Existe(slot)) return new DadosSave();

        try
        {
            var dados = JsonUtility.FromJson<DadosSave>(File.ReadAllText(Caminho(slot)));
            return dados == null ? new DadosSave() : Migrar(dados);
        }
        catch (Exception e)
        {
            // Arquivo corrompido: jogar uma partida nova é melhor que travar
            Debug.LogWarning($"Save {slot} ilegível ({e.Message}). Começando do zero.");
            return new DadosSave();
        }
    }

    public static void Apagar(int slot = 0)
    {
        if (Existe(slot)) File.Delete(Caminho(slot));
    }

    // Saves de versões antigas ganham valores padrão para campos novos
    private static DadosSave Migrar(DadosSave d)
    {
        if (d.versao < 2 && d.vida <= 0) d.vida = 3;
        d.versao = DadosSave.VersaoAtual;
        return d;
    }
}

Três cuidados já aparecem neste código: gravação atômica (arquivo temporário e troca), tolerância a falhas (try/catch devolvendo uma partida nova) e versão (jogadores com saves antigos continuam podendo jogar quando você acrescenta campos).

Ligando o save ao jogo

O save lê e escreve o estado dos seus componentes. Um componente fino faz a ponte:

PontoDeSave.cs 
using UnityEngine;

public class PontoDeSave : MonoBehaviour
{
    [SerializeField] private Transform jogador;
    [SerializeField] private Vida vida;

    public DadosSave Capturar()
    {
        var dados = new DadosSave();
        dados.vida = vida.Atual;
        dados.posicao = jogador.position;
        dados.pontos = GerenteDeJogo.Instancia != null ? GerenteDeJogo.Instancia.Pontos : 0;
        return dados;
    }

    public void Aplicar(DadosSave dados)
    {
        // CharacterController ignora a posição se estiver ligado: desligue por um instante
        var controle = jogador.GetComponent<CharacterController>();
        if (controle != null) controle.enabled = false;
        jogador.position = dados.posicao;
        if (controle != null) controle.enabled = true;

        vida.Curar(dados.vida - vida.Atual);
    }

    [ContextMenu("Salvar agora")] private void Salvar() => SistemaSave.Salvar(Capturar());
    [ContextMenu("Carregar agora")] private void Carregar() => Aplicar(SistemaSave.Carregar());
}

Salve pelo menu de contexto

Em Play, clique com o botão direito no componente e escolha Salvar agora. Abra a pasta mostrada em Application.persistentDataPath (imprima-a com Debug.Log) e confira o arquivo.

Mude o estado e carregue

Ande, leve dano e escolha Carregar agora. O herói deve voltar ao ponto salvo com a vida salva.

Estrague o arquivo de propósito

Apague metade do texto do JSON e carregue de novo. O jogo precisa continuar rodando, com um aviso no Console.

Checkpoint: o jogo grava e restaura posição, vida e pontos, e não quebra quando o arquivo está corrompido ou não existe.

Boas práticas por mecânica

MecânicaO que salvarCuidado
PlataformaÚltimo checkpoint, coletáveis já pegosSalvar o identificador do checkpoint, não a posição exata
StealthFase, itens, alarmes já disparadosNão salvar posição dos guardas: recriar a rota ao carregar
SurvivalInventário, fome, sede, hora do dia, construçõesLista longa: use versão e migração
CorridaMelhores tempos, carros liberadosDados pequenos e leves: bom caso para PlayerPrefs
PuzzleFases concluídas e estrelasSalvar depois de cada fase, não só ao sair

Checkpoint do módulo

  • uma classe de dados serializável com versão;
  • gravação atômica e leitura com tratamento de arquivo ausente ou corrompido;
  • pelo menos 3 informações da partida salvas e restauradas;
  • configurações simples guardadas com PlayerPrefs;
  • um teste documentado com arquivo apagado e arquivo estragado.

As instruções completas estão na Atividade Prática C10.

Problemas comuns

O arquivo não aparece onde esperava

Imprima Application.persistentDataPath no Console: o caminho muda por sistema e por nome do projeto. No Windows fica em AppData\LocalLow.

Um dicionário ou propriedade não foi salvo

A JsonUtility só grava campos públicos ou marcados com [SerializeField], e não grava dicionários. Converta para lista de itens simples.

Ao carregar, o herói volta para a posição errada

O CharacterController ligado ignora mudanças de posição. Desligue-o, mova e ligue de novo, como no PontoDeSave.

Depois de acrescentar um campo, saves antigos dão valores zerados

Isso é esperado: campos novos vêm com o padrão do tipo. Use a versao e a função de migração para definir valores corretos.
