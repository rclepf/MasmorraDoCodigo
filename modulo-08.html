Ligação com a UC anterior

Na UC anterior você desenhou a planta do cenário: salas, corredores, portas. Essa planta já era, sem você saber, um grafo: cada sala é um ponto e cada passagem é uma ligação. É com essa ideia que o computador "enxerga" o mapa e decide por onde um personagem deve andar.

Dica de produção. Mantenha as passagens com pelo menos 1 m de largura e os degraus e rampas com inclinação suave. A navegação automática depende da geometria que você modelou: um corredor estreito demais simplesmente não será considerado caminhável.

O mapa como grafo

Um grafo é um conjunto de nós ligados por arestas. Em jogos, os nós podem ser salas, células de um tabuleiro, pontos de patrulha ou polígonos do piso.

Perguntas que um grafo responde: existe caminho entre A e B? Qual o menor? Quais salas posso alcançar sem passar pela porta trancada? A resposta clássica é a busca em largura (BFS): explora a partir da origem, camada por camada, e o primeiro encontro com o destino é o caminho mais curto.

BuscaEmLargura.cs 
using System.Collections.Generic;
using UnityEngine;

public static class BuscaEmLargura
{
    private static readonly Vector2Int[] vizinhos =
    {
        Vector2Int.up, Vector2Int.down, Vector2Int.left, Vector2Int.right
    };

    // bloqueado[x, y] == true significa parede. Devolve a lista de células, ou null se não houver caminho.
    public static List<Vector2Int> Caminho(bool[,] bloqueado, Vector2Int origem, Vector2Int destino)
    {
        int largura = bloqueado.GetLength(0), altura = bloqueado.GetLength(1);
        var veioDe = new Dictionary<Vector2Int, Vector2Int>();
        var fila = new Queue<Vector2Int>();

        fila.Enqueue(origem);
        veioDe[origem] = origem;

        while (fila.Count > 0)
        {
            Vector2Int atual = fila.Dequeue();
            if (atual == destino) return Reconstruir(veioDe, origem, destino);

            foreach (Vector2Int d in vizinhos)
            {
                Vector2Int prox = atual + d;
                bool dentro = prox.x >= 0 && prox.y >= 0 && prox.x < largura && prox.y < altura;
                if (!dentro || bloqueado[prox.x, prox.y] || veioDe.ContainsKey(prox)) continue;

                veioDe[prox] = atual;
                fila.Enqueue(prox);
            }
        }
        return null;
    }

    private static List<Vector2Int> Reconstruir(Dictionary<Vector2Int, Vector2Int> veioDe, Vector2Int origem, Vector2Int destino)
    {
        var caminho = new List<Vector2Int>();
        for (Vector2Int c = destino; c != origem; c = veioDe[c]) caminho.Add(c);
        caminho.Add(origem);
        caminho.Reverse();
        return caminho;
    }
}

Repare no dicionário veioDe: ele serve ao mesmo tempo para não visitar a mesma célula duas vezes e para remontar o caminho de trás para frente. É um bom exercício de Queue, Dictionary e List.

E o A*? O A* é uma BFS mais esperta: em vez de explorar em todas as direções, ela prefere os nós que parecem mais perto do destino, somando o custo já andado e uma estimativa do que falta (a heurística, geralmente a distância em linha reta). Encontra o mesmo caminho curto explorando muito menos células. A Unity usa uma variação dele por dentro do NavMesh.

Teste em uma grade pequena

Crie um script de teste com um bool[,] de 8 por 8, algumas paredes e chame BuscaEmLargura.Caminho entre dois cantos. Imprima cada célula do resultado com Debug.Log.

Desenhe o caminho

Use Debug.DrawLine entre células consecutivas, convertendo x,y em x,0,y do mundo. Ver o caminho na aba Scene mostra se a lógica está certa.

Feche a passagem

Marque uma célula-chave como parede e veja o caminho contornar ou o método devolver null. Esse é o resultado que o seu jogo precisa tratar sem quebrar.

Checkpoint: o caminho é o mais curto possível, contorna as paredes e o método devolve null quando o destino está isolado.

NavMesh: o mapa automático da Unity

Em um cenário 3D, dividir o piso em células à mão é trabalhoso. A Unity oferece o NavMesh: uma malha simplificada que cobre todo o chão em que um agente pode andar, gerada automaticamente a partir da geometria do cenário. É o grafo, feito para você, em que cada polígono do piso é um nó.

Instale o pacote

Abra Window > Package Manager, escolha Unity Registry, procure AI Navigation e clique em Install. No Unity 6 esse pacote traz o componente NavMesh Surface.

Crie a superfície

Em um objeto vazio chamado Navegacao, adicione NavMesh Surface. Em Collect Objects deixe All Game Objects e clique em Bake. Uma área azul aparece sobre o chão caminhável.

Marque o que é obstáculo

Paredes e pilares entram no cálculo automaticamente. Para algo que não deve bloquear (decoração pequena), desmarque-o ou use Not Walkable no componente NavMesh Modifier.

Ajuste o agente

Em Agents, o raio, a altura e a inclinação máxima definem o que conta como caminhável. Se o corredor ficou fora do azul, o raio do agente é maior que a passagem: diminua o raio ou alargue o modelo no Blender.

Com o NavMesh pronto, um inimigo precisa apenas de um componente NavMeshAgent e de alguém que diga para onde ir:

PerseguidorNavMesh.cs 
using UnityEngine;
using UnityEngine.AI;

[RequireComponent(typeof(NavMeshAgent))]
public class PerseguidorNavMesh : MonoBehaviour
{
    [SerializeField] private Transform alvo;
    [SerializeField] private float velocidade = 3.5f;
    [SerializeField] private float distanciaParar = 1.2f;
    [SerializeField] private float intervaloRecalculo = 0.25f;

    private NavMeshAgent agente;
    private float proximoRecalculo;

    void Awake()
    {
        agente = GetComponent<NavMeshAgent>();
        agente.speed = velocidade;
        agente.stoppingDistance = distanciaParar;
    }

    void Update()
    {
        if (alvo == null || !agente.isOnNavMesh) return;
        if (Time.time < proximoRecalculo) return;

        // Recalcular a cada quadro é desperdício: 4 vezes por segundo basta
        agente.SetDestination(alvo.position);
        proximoRecalculo = Time.time + intervaloRecalculo;
    }
}

Compare com o módulo anterior: no InimigoIA, o método Mover andava em linha reta e batia nas paredes. Agora a decisão (perseguir) continua sendo da máquina de estados, mas o caminho é do NavMesh. É assim que se divide o trabalho em jogos reais.

Checkpoint: o inimigo contorna paredes e esquinas para chegar até você e para a uma distância de ataque, sem tentar atravessar nada.

Portas, rampas e obstáculos que se movem

SituaçãoSolução
Porta que abre e fechaNavMeshObstacle com Carve ligado: quando a porta está fechada, o buraco no NavMesh bloqueia o caminho
Caixa que o jogador empurraNavMeshObstacle em modo Carve, com Move Threshold para não recalcular o tempo todo
Piso de lama ou água rasaÁrea com custo maior: o agente evita, mas pode atravessar se for o único caminho
Salto ou queda de uma plataformaOff-Mesh Link ligando dois pontos do NavMesh
Stealth, Survival, Corrida, Puzzle e Plataforma. Stealth usa áreas de custo para os guardas evitarem a luz; Survival usa o NavMesh para perseguições longas; Corrida usa pontos de passagem na pista; Puzzle usa a BFS em grade para validar se a fase tem solução; Plataforma usa Off-Mesh Links nos saltos.

Checkpoint do módulo

  • uma busca em largura funcionando em uma grade, com teste de caso sem caminho;
  • um NavMesh gerado para a fase do jogo da equipe;
  • pelo menos um inimigo usando NavMeshAgent para perseguir ou patrulhar;
  • um obstáculo dinâmico (porta ou caixa) que altera o caminho em tempo de execução;
  • um print da aba Scene com o NavMesh visível e o caminho de um agente.

Problemas comuns

O agente avisa que não está sobre um NavMesh

O inimigo foi posicionado fora da área azul ou o NavMesh não foi gerado. Reposicione-o sobre o chão e clique em Bake de novo.

O NavMesh não cobre um corredor

O corredor é mais estreito que o raio do agente ou tem degraus altos. Ajuste as medidas do agente em Agents ou o modelo no Blender.

Depois de mover uma parede, o caminho continua antigo

O NavMesh gerado é estático. Para objetos que se movem, use NavMeshObstacle com Carve, ou gere o NavMesh de novo em tempo de execução.

A busca em largura trava o jogo em um mapa grande

Mapas grandes pedem A* e cálculo espalhado em vários quadros. Para a UC, mantenha as grades pequenas ou use o NavMesh.
